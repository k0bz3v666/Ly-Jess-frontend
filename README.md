# Ly-Jess — фронтенд

Простий фронтенд інтернет-зоомагазину Ly-Jess на чистих HTML, CSS і JavaScript (ES-модулі), без збірки й залежностей. Працює з бекендом із репозиторію `REST-API-Design`.

## Функціонал

| Сторінка | Файл | Хто бачить |
|---|---|---|
| Каталог товарів із пошуком | `index.html` | усі |
| Реєстрація | `register.html` | лише неавторизовані |
| Вхід | `login.html` | лише неавторизовані |
| Профіль (дані з `GET /api/auth/me`) | `profile.html` | лише авторизовані |
| Керування каталогом (додати й видалити товар) | `admin.html` | лише адміністратори |

Поведінка:

- Неавторизований користувач, який відкриває `profile.html` або `admin.html`, потрапляє на `login.html?next=<сторінка>`, а після входу повертається на цю сторінку.
- Авторизований користувач не може відкрити `login.html` і `register.html`: його перенаправляє на каталог.
- Гість у шапці бачить «Увійти» та «Реєстрація». Авторизований бачить своє ім'я та кнопку «Вийти».
- Logout видаляє токени з `localStorage` і повертає на каталог.
- Форма реєстрації показує помилки валідації від бекенду по кожному полю.
- Параметр `next` приймається лише у вигляді імені нашої сторінки (`profile.html`), тому через нього не можна відправити користувача на чужий сайт.
- Сторінка адмінки приховується для звичайних користувачів лише для зручності. Справжній захист на бекенді: він відповість `403` на будь-який запис без прав адміністратора.

### Як працюють токени

Код у `js/auth.js`.

1. Після логіну `access` (живе 5 хв) і `refresh` (живе 1 день) зберігаються в `localStorage`.
2. Захищені запити йдуть через `authFetch`: він додає `Authorization: Bearer <access>`.
3. Якщо `access` уже прострочений (`exp` у токені) або сервер відповів `401`, `authFetch` викликає `POST /api/auth/refresh`, зберігає новий `access` і **один раз** повторює запит. Одночасні запити діляться одним викликом refresh.
4. Якщо `refresh` недійсний, сесія очищається, і користувача перенаправляє на логін.
5. Відкриті запити (каталог) йдуть через `publicFetch` без токена, бо прострочений токен у заголовку дав би `401` навіть на публічному `GET`.

Токени лежать у `localStorage`, тому їх може прочитати будь-який JavaScript на сторінці (ризик XSS). Для навчального проєкту це прийнятно. У продакшені refresh токен краще віддавати в `HttpOnly`-cookie. Усі дані від користувача й сервера вставляються на сторінку через `textContent`, а не `innerHTML`, щоб не створювати XSS.

## Як запустити

1. Запустіть бекенд (див. README репозиторію `REST-API-Design`): `python manage.py runserver`. API має бути на `http://127.0.0.1:8000/api`. Для адмінки створіть адміністратора: `python manage.py createsuperuser`.
2. Віддайте фронтенд будь-яким статичним сервером. ES-модулі не працюють при відкритті файлу напряму (`file://`).
   - Python: `python -m http.server 8080` у цій папці, потім `http://127.0.0.1:8080`.
   - Або розширення VS Code **Live Server** (порт `5500`).
3. Порти `3000`, `5173`, `5500` і `8080` уже дозволені в CORS бекенду. Якщо використовуєте інший, додайте його в `CORS_ALLOWED_ORIGINS` у `config/settings.py`.

Адреса бекенду змінюється в `js/config.js`.

## Структура

```
index.html, login.html, register.html, profile.html, admin.html
css/style.css
js/config.js    адреса API
js/auth.js      токени, authFetch/publicFetch, login/logout, redirect-и
js/ui.js        шапка, повідомлення, форматування помилок
js/<page>.js    логіка кожної сторінки
```
